# הפצת כתוב · 1.3.0

## מצב ותנאי פרסום

גרסה 1.3.0 מופצת כגרסת ניסיון ללא חתימה דיגיטלית וללא תשלום. המתקין מסומן `UNSIGNED`, והפרסום ב־GitHub מסומן `Pre-release`. התהליך מפרסם רק לאחר בדיקות הקוד, ביקורת תכולה, התקנה והסרה של ה־EXE ואימות SHA-256. בדיקת CI אינה מחליפה בדיקות קבלה בחשבון רגיל ב־Windows 10/11 במחשב נוסף; הכרזה על גרסה יציבה ממתינה להן, אך אינה דורשת רכישת תעודה.

היעד הוא Windows 10/11 x64 עם Intel/AMD. אין מתקין נתמך ל־ARM, macOS או Linux. ממשק הדפדפן מקומי בלבד; אין טלפון, שרת LAN או עיבוד מדיה בענן.

## הורדה ואימות

הורידו את `Katuv-1.3.0-Windows-UNSIGNED.exe` וקובץ ה־`.exe.sha256` מאותו פרסום ב־[מאגר הרשמי](https://github.com/dvicabi/katuv/releases). בתיקיית ההורדות, הריצו ב־PowerShell:

```powershell
Get-FileHash -LiteralPath '.\Katuv-1.3.0-Windows-UNSIGNED.exe' -Algorithm SHA256
Get-Content -LiteralPath '.\Katuv-1.3.0-Windows-UNSIGNED.exe.sha256'
```

64 התווים של החותמת צריכים להתאים (ללא הבדל בין אותיות גדולות לקטנות). אם הם שונים, אל תפעילו את הקובץ. SHA-256 מאפשר לבדוק שההורדה תואמת לתוצר שפורסם; הוא אינו תעודה לזהות המפרסם.

בגרסה זו Windows עשוי להציג ״מפרסם לא ידוע״ או ״Windows הגן על המחשב שלך״. לאחר בדיקת המקור והחותמת, ניתן לבחור ״מידע נוסף״ / `More info` ואז ״הפעל בכל זאת״ / `Run anyway`, אם Windows מציע זאת. אין צורך לכבות אנטי־וירוס או לשנות את הגדרות SmartScreen. במחשב מנוהל ייתכן שהמדיניות הארגונית לא תאפשר הרצה.

## התקנה, שדרוג והסרה

המתקין העברי משתמש ב־Inno Setup 7.1.1 ומתקין תחת `%LOCALAPPDATA%\Katuv` ללא הרשאות מנהל. ההכנה דורשת אינטרנט ולפחות 10 GB פנויים. Python 3.11 מנוהל, תלויות נעולות ו־FFmpeg מורדים בנפרד. מודלים יורדים דרך מסך ״הכנת המחשב״; דוגמת היישום אינה דורשת מודלים.

כל התקנה, תיקון או עדכון יוצרים סביבת `runtime-<version>-<uuid>` חדשה. נבדקים התלויות, טעינת רכיבי ההתאמה וייצוא עברי אמיתי לפני החלפת `active-runtime.txt`. הגרסה הקודמת נשמרת ב־`previous-runtime.txt`. תהליך שנכשל אינו מתקין חבילות לתוך הסביבה הפעילה. אפשר להריץ את המתקין שוב.

התקנה, הפעלה והסרה משתמשות בנעילה משותפת. לפני עצירת שרת נבדקים נתיב תהליך ה־Python, מזהה ההתקנה, הסביבה הפעילה ומצב עיבוד/הכנה. גרסה 1.2 נבדקת באמצעות בעלות התהליך ונקודות המצב הישנות. שרת שאינו מגיב אינו נעצר אוטומטית. אין עצירה של שרתי פיתוח או התקנות אחרות.

הסרה דרך הגדרות Windows מסירה את סביבות האפליקציה וקיצורי הדרך שלה. פרויקטים, מודלים, Python מנוהל ומטמוני רכיבים נשמרים כדי לאפשר התקנה חוזרת. לפינוי מלא: גיבוי `projects`, סגירת היישום, ורק לאחר מכן הסרת תיקיית Katuv ידנית. מטמוני Hugging Face ו־Torch משותפים עשויים לשמש תוכנות אחרות ואינם נמחקים.

## תקלות והתאוששות

- קובץ פרויקט פגום מופיע כפרויקט שלא ניתן לפתוח. שאר הפרויקטים והיישום ממשיכים לעבוד; הקובץ הפגום נשמר ללא שינוי.
- העלאה שנקטעה, קובץ לא תקין או חוסר מקום אינם משאירים תיקיית פרויקט חלקית חדשה.
- בפורט תפוס אין חיבור שקט לשרת אחר. ניתן לסגור אותו או להפעיל `Start-Katuv.ps1 -Port 8771`.
- יומנים: `installation.log`, `server.err.log`. לפני דיווח ציבורי יש להסיר מידע פרטי; אין העלאת יומנים אוטומטית.
- אין סנכרון ענן. גיבוי נעשה בהעתקת `projects` בשלמותה כשאין עיבוד פעיל.

## ממשקי תחזוקה ותאימות

`GET /api/health` שומר את `app`, `version: 2`, `local`, `device` ומוסיף `app_version`, `installation_id`, `runtime_id`, `busy`, `maintenance`. `busy` כולל עיבוד וגם הכנת מודלים.

`POST /api/system/maintenance` מקבל `{ "enabled": true|false }`: כניסה נכשלת ב־409 בעת עבודה; בעת תחזוקה פעולות חדשות נחסמות. `PUT /api/system/preferences` מקבל `{ "include_noncommercial": true|false }` ושומר את הבחירה ב־`.preferences.json` בתיקיית הפרויקטים. שינוי בעת עבודה נחסם. ברירת המחדל היא false, ומשקלים במטמון אינם תחליף להסכמה. תוצאות מדידה שמורות של MMS מסוננות כשאין הרשאה לשימוש בו; תזמונים קיימים שהמשתמש שמר אינם נמחקים.

העדפות חדשות אינן משנות את מבנה הפרויקטים מ־1.2. התמליל, העריכות הידניות, בחירת המודל ורזולוציית הייצוא נשמרים.

## בנייה ובדיקות

```powershell
python -m pytest -q
python -m pytest tests/test_model_integration.py --run-model --run-hebrew-models -q
python scripts/build_release.py --exe --iscc "C:\Program Files\Inno Setup 7\ISCC.exe"
```

במחשב שבו תיקיית pytest הזמנית אינה נגישה, אפשר להעביר `--basetemp` לנתיב חדש וייחודי בתוך `.test-output`. pytest מוחק תוכן קיים בנתיב זה: אין להעביר תיקיית פרויקטים או תיקייה עם מידע חשוב.

הבנייה משתמשת בעותק זמני מרשימת קבצים מוגדרת, בודקת את תכולת ה־ZIP וה־wheel ומצמידה גרסה ו־commit למניפסט. אין אריזה של סביבות, סרטוני משתמש, צילומי פרויקטים או משקלי מודלים. פרטי חתימה ובדיקות קבלה ב־[code-signing.md](code-signing.md).

רזולוציות הייצוא: מקור, 720p, 1080p, 1440p, 2160p. המספר מגדיר את הצלע הקצרה; יחס התצוגה, האודיו וקצב הפריימים נשמרים. הגדלה אינה משחזרת פרטי תמונה חסרים.
